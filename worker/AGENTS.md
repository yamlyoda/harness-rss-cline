# Worker AGENTS.md

## Правила сервиса

- Если меняешь обработчик очереди NATS (FastStream), помни: доставка может быть повторной, запись должна быть идемпотентной.
- Если работаешь с моделью spaCy (`ru_core_news_sm`), модель загружается один раз при старте, а не на каждое сообщение.
- Если пишешь новость и сущности в PostgreSQL, делай это в одной транзакции.
- Если сообщение из NATS не проходит валидацию, не останавливай воркер; зафиксируй проблему и пропусти или отложи сообщение.
- Если меняешь структуру записи в БД, сначала читай `docs/architecture/data-model.md`.
- Если меняешь контракт сообщения из NATS, сначала читай `docs/architecture/message-contract.md`.
- Если добавляешь новый тип сущности (label), не меняй старый контракт без новой версии.
- Если правишь только локальную логику воркера, не выноси детали в корневой `AGENTS.md`.
